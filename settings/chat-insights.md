## 2. Критично: что известно про задачу

- **Полный текст кейса, критерии оценки, формат сдачи, ограничения на LLM — только 19.10.** До этого организаторы ничего не уточняют, на все вопросы отвечают «будет в тексте кейса».
- **Данные дадут, и их обязательно нужно использовать** (06.10.2026: «на треках будут предоставлены свои данные, которые необходимо будет использовать»).
- **Лидерборда у нашего трека нет.** Решение проверяют эксперты вручную по техническим критериям (22.09.2026).
- **Баллы и места после отбора не раскрывают** (18.10.2026). В финал проходят 10 команд с трека.
- Готовиться заранее по описанию с сайта правилами не запрещено (18.09.2026).

## 3. Критично: ресурсы и LLM

- **Ни серверов, ни GPU, ни API к LLM на отборе не дают** (07.10 и 15.10.2026). Доступа к AlfaGen тоже не будет (30.09.2026). Хостинг — свой.
- Ограничения на LLM (отечественные/зарубежные, платные/бесплатные) будут **в тексте кейса, у каждого трека свои**.
- **Прецедент 2025 года для copilot-трека (наш ближайший аналог):**
  - сначала разрешили платные API по токенам, а в день публикации кейса **запретили всё, что тарифицируется** — даже бесплатные стартовые токены и платные обёртки над бесплатными моделями;
  - разрешили только бесплатные/открытые модели, например бесплатные модели OpenRouter;
  - **ключ доступа нужно было оставить в коде**, чтобы эксперты могли запустить;
  - модель должна работать **в любой день до объявления результатов**, поэтому нельзя упираться в дневные лимиты (у бесплатного OpenRouter ~50 запросов в день и частые rate-limit).
- **Вывод для нас:** LLM-слой делаем за абстракцией (OpenAI-совместимый клиент, провайдер и модель меняются через env). Ассистент должен деградировать корректно: если LLM недоступна, кабинет и вся бизнес-логика продолжают работать.

## 4. Критично: как сдавали и проверяли в 2025 (copilot-трек)

- Решение — **код**. Проверяют запуском локально **или** через задеплоенный сервер, который живёт на время проверки.
- Сдача: документ со ссылкой на репозиторий (в 2025 — публичный) в разделе загрузки решения в ЛК.
- Docker-образ не влез в загрузку — разрешили ссылку на репозиторий и инструкцию по сборке.
- Несколько команд жаловались, что эксперты **не зашли ни в сервис, ни в репозиторий** (видно по логам), или склонировали репо, но не смогли запустить.
  Значит, запуск у эксперта должен быть тривиальным.
- Презентация на отборе в 2025 не требовалась, оценивали README и работающий продукт. В 2026 формат могут поменять — смотрим кейс.

**Отсюда обязательные вещи:**
1. `docker compose up` поднимает всё одной командой, с seed-данными.
2. Задеплоенный стенд по HTTPS, который не падает до конца ноября.
3. README: что сделано, как запустить, демо-логины, сценарий проверки по шагам, скриншоты.
4. Логи доступа на стенде — чтобы видеть, проверяли ли нас, и вовремя написать оргам.

## 5. Важно: правила

- **Репозиторий создаём сами.** Приватный можно, но к проверке нужно дать доступ экспертам (07.10, 16.10.2026).
- **Данные кейса не кладём в публичный репозиторий.** В 2024 выгрузка данных на GitHub грозила дисквалификацией. В 2025 GitHub разрешили, но хранить и распространять материалы после соревнования запрещено.
  → данные держим вне git (`.gitignore`), в репо только скрипт загрузки.
- **ChatGPT, Copilot, Claude и т.п. для разработки разрешены.** Оценивается результат и бизнес-ценность, а не инструменты. Но **предоставленные данные нельзя передавать во внешние сервисы, если это запрещено кейсом** (14.10.2026) — это касается и вставки данных в чат с ИИ.
- Чужой код и открытые репозитории — **указываем автора в сопроводительных материалах** (07.10.2026).
- Исключительные права на итоговые материалы, включая код, принадлежат организатору с даты создания (06.10.2026).
- В 2025 n8n разрешали, но с выдачей доступа экспертам к логике.
- Язык и стек не ограничены (в 2025 для copilot-трека — без ограничений). FastAPI + Vue подходят.

- Письма приходят с `reply@cl-friends.com` — проверять «Спам». Сайт Changellenge лучше открывать в Chrome (в Firefox были проблемы с входом).

## 7. Дополнение: чат «Флудилка» (2025–2026)

В основном мемы и реклама. Полезного немного:

- **Формулировка нашего трека с сайта** (её процитировал участник 17.10.2026): «Персонализировать подбор кредита — создайте ИИ-кабинет, который помогает предпринимателю выбрать и оформить подходящий кредит». Роли: ML, Data Science, Front, Back.
- **Copilot-2025, как проверяли на самом деле:** по тексту кейса эксперты **разворачивали решение локально из репозитория**, даже если был задеплоенный сервер. Поэтому и просили оставить API-ключи в коде.
  На задеплоенные стенды почти никто не заходил («1 промпт отправили, на этом всё»). Команды переживали, что их README недостаточно подробный.
  → **Главный артефакт — репо + README + docker compose, а стенд идёт бонусом.**
- **Модель, которую команда использовала, за время проверки перестала быть бесплатной.** Значит, нужен запасной провайдер и переключение через env, без правки кода.
- **На эфире с результатами 2025 эксперты RAG-трека спрашивали «А где эксперименты?».** Команда, вычистившая репо до финального скрипта, получила претензию, что «не экспериментировали».
  → Не прячем ход работы: ветки и история коммитов остаются, решения с обоснованием — в документах модулей (разделы «Решения и упрощения», «Упрощения»), версии политики и модели — в [`decision.md`](../docs/modules/decision.md) и [`scoring.md`](../docs/modules/scoring.md). Отдельного `docs/decisions.md` нет.
- **Ведущий copilot-трека на эфире поднимал вопрос «LLM по API vs локальная модель»** для внедрения в банк. Готовим ответ: LLM за интерфейсом, в банке подменяется на внутреннюю модель без переделки.
- Финалисты copilot-2025 делали кто веб, кто Telegram-бота, кто мобилку. Формат клиента не фиксирован — смотрим кейс.

## 8. Ответы организаторов после публикации кейса (чат трека)

- **Предприниматель уже клиент банка.** Основные сведения о компании (ИНН, наименование, данные учредителей и т.д.) считаются уже известными системе. Повторную регистрацию и сбор полного пакета документов реализовывать не нужно. Что предзаполнять, а что дозапрашивать при оформлении заявки — решает команда.
- **Экран регистрации и входа не обязателен.** Можно сделать упрощённый вход (например, по номеру телефона) или взять готовый демо-профиль без отдельной авторизации. Главное — чтобы основной сценарий кредитного конвейера работал и был доступен для проверки.

→ Регистрацию и онбординг компании не делаем: пользователи и компании приходят из seed, данные компании предзаполняются в заявке. Вход нужен нам для разделения ролей (клиент / сотрудник банка) и RBAC/ABAC, а не эксперту. Эксперту — демо-учётки и вход в один клик. Подробнее — [`settings/case.md`](case.md), раздел 5.

- **LLM через внешний API (25.10.2026).** OpenRouter можно использовать для обращения к моделям с открытыми весами; 120 млрд параметров — рекомендация, а не жёсткое ограничение. Свой API-ключ в репозитории оставлять не нужно. Важно, чтобы подключение было совместимо с OpenAI API и позволяло настроить base URL, API-ключ и название модели; процесс настройки описать в README, чтобы эксперты могли подключить собственного провайдера при проверке.

→ Модель помощника — за интерфейсом в модуле backend `assistant`: `ASSISTANT_LLM_PROVIDER=local` (Ollama, по умолчанию) или `api` (base URL, ключ, модель), закрытые модели отклоняются по названию. Инструкция — README, раздел «С ИИ: свой провайдер», подробно — [`docs/ai.md`](../docs/ai.md).
