# ML-модель скоринга

Статистическая модель вероятности дефолта (WoE + логистическая регрессия), которая работает
рядом с экспертной PD-моделью `pd_model_v2`: скоринг считает обе на каждой заявке, решение
(`policy_v5`) смотрит на обе, расхождение уходит андеррайтеру (см. «Две модели» в
`docs/modules/scoring.md`).

| Файл | Что это |
|---|---|
| `population.py` | синтетическая популяция заявок (`ScoringInput`) с отдельным «истинным» процессом дефолта |
| `train.py` | WoE-биннинг, отбор по IV и знаку, логрегрессия, экспорт YAML, метрики, отчёт, фикстура паритета |
| `validate.py` | проверки честности: бутстрап значимости, устойчивость к допущениям, сравнение при «правде» = PD-модель |
| `reports/ml_logreg_v1.md` | отчёт: данные, Gini/KS/ROC-AUC, калибровка, PSI, грейды, матрица зон, IV, коэффициенты |
| `reports/ml_validation.md` | результаты проверок честности |

```bash
cd backend
uv sync --group ml                      # pandas, scikit-learn — только локально
uv run --group ml python -m ml.train    # переобучить: YAML, отчёт, фикстура паритета
uv run --group ml python -m ml.validate # проверки честности (несколько минут)
```

Результат обучения — `src/modules/scoring/infrastructure/config/ml_logreg_v1.yaml`; инференс —
`src/modules/scoring/domain/ml_model.py` (чистый Python на `Decimal`). Границы грейдов A–I
обучение берёт из `pd_model_v2.yaml`, чтобы грейды двух моделей были на одной шкале. Обучение
детерминировано (seed), тест `tests/scoring/unit/test_ml_model.py` проверяет, что прод считает
ровно то, что выгрузило обучение.
