# Clients: компании и права внутри них

Кто заёмщик и кто имеет право действовать от его имени. Предприниматель уже клиент банка (ответ организаторов, `docs/case.md` §5): регистрации и онбординга компании нет, компании, участники и реквизиты — в сидах, заявка предзаполняется снимком компании. Код — `backend/src/clients`.

## Модель

| Что | Где | Суть |
|---|---|---|
| `Organization` (агрегат) | `domain/organization.py` | Реквизиты, наименование, дата регистрации, адрес, ОКВЭД, налоговый режим, численность, статус в реестре, руководитель по реестру, результат сверки, участники |
| `Member` | `domain/member.py` | `account_id`, роль, полномочие, доверенность, кто и когда добавил. Меняется только через агрегат |
| `FinancialReport` (агрегат) | `domain/financial_report.py` | Показатели за период (год или квартал) из одного источника: `declared`, `fns`, `bank_statement` |
| Права | `domain/rights.py` | `OrgPermission`, роли, полномочия, `PowerOfAttorney`, таблица прав |
| VO | `domain/value_objects.py` | `Inn`, `Ogrn`, `Kpp`, `Requisites`, `OkvedCode`, `Address`, `FiscalPeriod`, `PersonName`, `VerificationResult` |

Все VO проверяют себя в конструкторе и бросают `ValidationError` с `details = {field, code}`:

| VO | Правило |
|---|---|
| `Inn` | 10 цифр (ЮЛ): контрольная цифра по весам `2,4,10,3,5,9,4,6,8`; 12 цифр (ИП): две контрольные по `7,2,4,10,3,5,9,4,6,8` и `3,7,2,4,10,3,5,9,4,6,8`; `sum % 11 % 10` |
| `Ogrn` | ОГРН — 13 цифр, первая 1 или 5, `int(v[:12]) % 11 % 10 == v[12]`; ОГРНИП — 15 цифр, первая 3, `int(v[:14]) % 13 % 10 == v[14]` |
| `Kpp` | `^\d{4}[\dA-Z]{2}\d{3}$` |
| `Requisites` | ИНН 10 ⇔ ОГРН 13 ⇔ LLC/JSC ⇔ есть КПП; ИНН 12 ⇔ ОГРНИП 15 ⇔ IE ⇔ КПП нет. Неизменяемы |
| `OkvedCode` | `^\d{2}(\.\d{1,2}){0,2}$`, раздел A…U по первым двум цифрам (несуществующий класс — ошибка) |
| `PersonName` | `normalized()` — нижний регистр, ё → е, одиночные пробелы; `repr()` маскирует ФИО, чтобы оно не попало в логи и трейсбеки |
| `PowerOfAttorney` | номер, `issued_at`, `valid_until` (включительно, даты UTC), `scope` ⊆ {`submit_application`, `sign`} |
| `VerificationResult` | `unverified` (без даты), `verified` (с датой), `mismatch` (с датой и расхождениями `field / declared / registry`) |

## Права внутри компании

`OrgPermission`: `view`, `submit_application`, `sign`, `manage_members`, `edit_financials`. Это не пермишны токена: токен говорит, какие ручки можно вызывать, права компании — что можно делать в конкретной компании.

| Роль | view | submit_application | sign | manage_members | edit_financials |
|---|---|---|---|---|---|
| owner / director | ✓ | ✓ | ✓ если полномочие подтверждено | ✓ | ✓ |
| accountant | ✓ | ✓ | только по действующей доверенности со scope `sign` | — | ✓ |
| employee | ✓ | по доверенности | по доверенности | — | — |

Полномочие (`authority`): `registry` — ФИО совпало с руководителем по реестру, `power_of_attorney` — есть доверенность, `unconfirmed` — ни того, ни другого. Права считаются на момент `now`: истёкшая доверенность перестаёт действовать сама, без фоновых задач.

## Инварианты

- Реквизиты не меняются (у агрегата нет сеттера, `Requisites` — frozen).
- Аккаунт в компании — не больше одного раза (`409 already_member`).
- В компании с участниками всегда есть кто-то с `manage_members`: последнего не удалить и не понизить (`409 last_manager`); первый участник обязан его иметь.
- Участниками управляет только участник с `manage_members` или банк (сиды, бэк-офис).
- Полномочие по реестру получает owner/director, чьё ФИО совпало с руководителем по реестру (`PersonName.matches`). Смена роли полномочие не подтверждает: повышенный до директора бухгалтер подписывать не может.
- Доверенность выдаёт только руководитель, подтверждённый реестром; себе — нельзя; просроченную — нельзя. Неподтверждённый директор (Петров в «Векторе») не может выдать доверенность ни себе, ни другим — иначе он обошёл бы проверку полномочий.
- Клиент заявляет только отчёты `declared`; отчёт — только за закончившийся период; повторная подача за тот же период и источник уточняет отчёт, а не создаёт второй.
- Подачу по `registry_status` не блокируем: стоп-фактор «ликвидация» применяет decision (S-4).

## ИП, ООО, АО

| | ИП (`IE`) | ООО (`LLC`) | АО (`JSC`) |
|---|---|---|---|
| ИНН / ОГРН | 12 / ОГРНИП 15 | 10 / 13 | 10 / 13 |
| КПП | нет | обязателен | обязателен |
| Руководитель по реестру | сам предприниматель | директор | директор |
| owner | ровно один — сам ИП: ФИО совпадает с реестром, сменить или удалить нельзя | учредители, сколько угодно | акционеры, сколько угодно |
| director | роли нет | руководитель | руководитель |
| Налоговый режим | любой, патент — только ИП | без патента | без патента |

АО в MVP устроено как ООО (особых ролей нет), но форма поддержана в VO, продуктах и правах.
