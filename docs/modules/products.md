# Модуль products

Каталог кредитов, подбор продукта с объяснением и калькулятор платежа. Продукт задаёт рамки (сумма, срок, ставка), кому он доступен и что должно быть в заявке; маршрут рассмотрения берёт process, рамки для решения — decision. Само решение по заявке — не здесь. Код — `backend/src/products`, каталог — `backend/seed/products.py`.

## Модель

Вид кредита — не один enum, а сочетание: **цель × форма предоставления × график × обеспечение × господдержка**.

| Измерение | Значения |
|---|---|
| Цель (`purposes`) | `working_capital`, `cash_gap`, `equipment`, `vehicles`, `real_estate`, `contract_execution`, `refinancing`, `expansion` — те же, что принимает заявка |
| Форма (`facility`) | `term_loan`, `credit_line_revolving`, `credit_line_non_revolving`, `overdraft` |
| График (`repayment_options`) | `annuity`, `differentiated`, `interest_only`, `by_contract_schedule`; первый — по умолчанию |
| Обеспечение (`security`) | залог `none` / `optional` / `required` + виды залога (как в заявке: `real_estate`, `equipment`, `vehicle`, `goods`); поручительство `none` / `owner` / `msp_corporation`; `collateral_required_from` — с какой суммы залог по желанию становится обязательным |
| Господдержка (`support_program`) | потолок ставки, требование реестра МСП, список классов ОКВЭД |

Агрегат `CreditProduct` (`domain/product.py`) держит ещё требования к заёмщику (`Eligibility`: срок работы, формы бизнеса, выручка, `startup_only` — только для стартапа), документы (`DocumentRequirement`: всегда / от суммы / для форм бизнеса), JSON Schema доп. полей заявки и `ProcessingProfile` (маршрут и лимит авторешения).

Инварианты: корректные диапазоны (сумма > 0, мин ≤ макс; срок 1–360 мес.; ставка 0–100 %), хотя бы одна цель, `auto_decision_limit ≤ amount.max`, порог залога — внутри диапазона суммы, потолок господдержки — внутри диапазона ставки, типы документов не повторяются. Нарушение — `ValidationError` с `details.field`.

Статусы: `draft → active → archived`. Архивный продукт читается (на него ссылаются старые заявки), но не выбирается: `snapshot()`, подбор, проверка и калькулятор отвечают `409 product_not_available`. Изменение условий — новая версия (`code` + `version` уникальны); заявка хранит копию условий (`ProductTerms`), поэтому правка каталога её не меняет. Текущая версия — последняя активная, иначе последняя архивная; черновик не виден.

Цели: UNSECURED — оборотка, развитие, рефинансирование, исполнение контракта; SECURED — оборотка, оборудование, развитие, рефинансирование; CREDIT_LINE — оборотка, кассовый разрыв, исполнение контракта; OVERDRAFT — кассовый разрыв; AUTO — транспорт; MORTGAGE — недвижимость; REFINANCE — рефинансирование; GOV_SUPPORT — оборотка, оборудование, развитие; STARTUP — оборотка, оборудование, развитие. Каждая цель заявки покрыта хотя бы одним продуктом (тест).

### Продукт для стартапа

Стартап — компания младше `STARTUP_AGE_MONTHS` (6 мес., `facade.py`) или без годовой отчётности: оборотов и выручки, по которым считают остальные продукты, у неё нет. Продукт с `Eligibility.startup_only` (в каталоге — `STARTUP`) доступен только стартапу: проверка заёмщика даёт причину `startup` — пройдена «Компания без оборотов и годовой отчётности — продукт для неё», не пройдена «Продукт для компаний младше 6 месяцев или без годовой отчётности; у вас есть обороты — подойдут другие продукты». Обычные продукты стартапу и так недоступны — по сроку работы или выручке.

Без автоматики: `auto_decision_limit` = 0, маршрут `startup_v1` — проектная оценка андеррайтером (бизнес-план, финмодель, обеспечение, господдержка). Заявку на `STARTUP` политика пускает только с пройденным предскрином учредителя, предодобрение по нему не считается — см. [decision](decision.md#ветка-стартапа-policy_v4-и-предскрин-учредителя). Демо — ООО «Старт» (3 мес., отчётности нет).

Различие форм бизнеса: бухгалтерскую отчётность (`financial_report`) просим у ООО и АО, у ИП — налоговую декларацию (`tax_return`); бизнес-ипотека — только для ООО и АО. Доп. поля заявки (JSON Schema, подмножество из `applications/domain/fields_schema.py`): AUTO — `vehicle_type`, `vehicle_description`, `supplier_name`, `price`; MORTGAGE — `property_address`, `property_type`, `price`; REFINANCE — `loans[]` (`creditor`, `outstanding`, `monthly_payment`, `rate`). Залог (`collateral` в заявке) обязателен у SECURED, AUTO и MORTGAGE.

## Подбор и причины

`ProductRecommender` (`domain/recommender.py`) детерминирован: цель → рамки → проверка заёмщика → ставка.

1. Кандидаты — активные продукты под цель. Если scoring прогнозирует кассовый разрыв, добавляются продукты для `cash_gap` (линия, овердрафт), даже при другой цели.
2. Порядок: сначала доступные и подходящие по рамкам, затем доступные, но с поправкой суммы или срока, в конце — недоступные компании. Внутри группы продукты чужого сегмента идут после своих: стартапу — обычные продукты после `startup_only`, остальным и подбору без компании — наоборот. Дальше при цели `cash_gap` или прогнозе разрыва первыми идут кредитная линия и овердрафт, затем — по базовой ставке для клиента, в конце — по порядку каталога. Кабинет (bff) показывает стартапу только продукты стартапа, остальным — без них.
3. Каждая рекомендация несёт `reasons` (`code`, `passed`, `message`) — их видит сотрудник банка: цель, кассовый разрыв, сумма, срок, все условия заёмщика, залог, ставка, будет ли авторешение. Поправки (`adjustments`) — тексты непройденных рамок, с лучшей альтернативой из доступных компании: «Максимум 30 млн ₽ — запросите 30 млн ₽ или выберите «Кредит с господдержкой» (до 100 млн ₽)».
4. Платёж «от/до» — по графику по умолчанию, по минимальной и максимальной ставке для клиента, для ближайших к запросу суммы и срока, которые допускает продукт.

Проверка заёмщика (`CreditProduct.check_eligibility`) даёт причину на каждое условие, пройденное или нет: «Нужно от 12 месяцев работы, у вас 8», «Нужна выручка от 10 млн ₽ в год, у вас 6 млн ₽», «ОКВЭД 62 входит в программу господдержки …». Не блокируют, только отмечаются (`passed = true`): статус по реестру (ликвидация — стоп-фактор decision, S-4), несверенные данные компании, неизвестное членство в реестре МСП («проверим по реестру при рассмотрении»). Пример на демо-данных: ИП Иванов (8 мес., ОКВЭД 62) — доступны UNSECURED, OVERDRAFT и AUTO; CREDIT_LINE и GOV_SUPPORT — нет по сроку работы (и выручке), при этом у GOV_SUPPORT пройдена причина по ОКВЭД.

`BorrowerProfile` собирается из `ClientsFacade.get_snapshot`: форма бизнеса, срок работы, выручка последнего годового отчёта, ОКВЭД, сверка с реестром, статус в реестре. Прогноз кассового разрыва — флаг `cash_gap` (или `cash_gap_*`) из `ScoringFacade.estimate`, если scoring подключён; без него или при ошибке scoring прогноз неизвестен и подбор работает без него.

## Калькулятор

`PaymentCalculator` (`domain/calculator.py`) — единственная формула платежа в системе (её же повторяет фейк `tests/fakes/products_facade.py`, тест сверяет их).

```
r  = ставка / 12 / 100
A  = round(P · r / (1 − (1 + r)^−n))          аннуитет; при r = 0: A = round(P / n)
Iₖ = round(Bₖ₋₁ · ставка / 1200)              проценты месяца k на остаток
тело месяца k: аннуитет — A − Iₖ; дифференцированный — round(P / n); только проценты — 0
последний платёж: тело = весь остаток
```

Только `Decimal`, округление до копеек `ROUND_HALF_UP`, аннуитет считается с точностью 50 знаков. Последний платёж добирает остаток, поэтому сумма тела всегда равна сумме кредита. `monthly_payment` — аннуитет, для других графиков — первый (наибольший) платёж. `by_contract_schedule` формулой не считается — `422`. Три эталонных графика в `tests/products/golden/*.json` посчитаны независимо (точная рациональная арифметика `fractions.Fraction`).

## API

| Метод | Путь | Доступ | Что |
|---|---|---|---|
| GET | `/products?purpose=` | без токена | витрина: активные продукты в порядке каталога |
| GET | `/products/{code}` | без токена | карточка; архивный — со `status: archived`, нет / черновик — 404 |
| POST | `/products/recommend` | без токена | подбор по потребности `{purpose, amount, term_months}` без проверки компании |
| POST | `/products/recommend/{organization_id}` | токен `credits.read` + участник компании | подбор для компании: причины проверки и прогноз разрыва |
| POST | `/products/{code}/calculate` | без токена | `{amount, term_months, rate?, repayment?}` — график в рамках продукта; по умолчанию базовая ставка и график продукта |
| GET | `/products/{code}/eligibility?organization_id=` | токен `credits.read` + участник компании | проверка компании по продукту |

Компания проверяется через `ClientsFacade.ensure_can(user, org, "view")`: чужая — 404, не 403. Админ и сотрудники банка (`organizations.read` без политики `org_member`) видят любую компанию. Публичный подбор не принимает `organization_id` (422): подбор для компании — отдельный путь, чтобы токен был обязателен ровно там, где нужен. Суммы и ставки в ответах — строки-`Decimal`.

## Фасад

`ProductsFacade` (`facade.py`), реализация `infrastructure/facade_impl.py`, подключается в `module.wire`:

| Метод | Что |
|---|---|
| `get_product(code)` / `list_active()` | продукт плоско (`ProductDTO`, в том числе `startup_only`) |
| `get_terms_snapshot(code)` | копия условий для новой заявки; `rate_max` — с учётом потолка господдержки; архивный — `ProductNotAvailableError` (409) |
| `check_eligibility(code, organization_id)` | причины проверки компании |
| `recommend(purpose, amount, term_months, organization_id?)` | рекомендации с `reasons`; `estimated_monthly_payment` — платёж «от» |
| `calculate_payment(amount, term_months, rate, repayment)` | синхронный, без рамок продукта |

Права на компанию фасад не проверяет — это делает вызывающий модуль. Константа `STARTUP_AGE_MONTHS` там же — по ней bff определяет сегмент компании.

## Хранение

Таблица `products_credit_products` (миграция `products_0001`): версия продукта на строку, `UNIQUE (code, version)`, суммы `Numeric(18, 2)`, ставки `Numeric(5, 2)`, списки, программа господдержки, документы и схема полей — JSONB. Флаг `startup_only` — с `products_0002`, по умолчанию `false`. Сид `seed/products.py` — upsert по `code` + `version`: повторный запуск оставляет тот же каталог.

## Упрощения

- Каталог меняется только сидом: API администрирования продуктов (`credits.create|update`) нет.
- Членства в реестре МСП в снимке компании нет — условие не блокирует подбор и проверяется при рассмотрении.
- Ставка в подборе — диапазон продукта; персональную ставку по риску назначает decision.
- Лимит овердрафта по оборотам счёта не считается: рамки продукта общие для всех.
- Даты платежей в графике не заполняются (`due_date = null`): дата выдачи известна только после подписания.
