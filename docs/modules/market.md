# market — рыночные параметры

Ключевая ставка Банка России и её история. Ставку читают products (сдвиг каталога за ключевой) и decision (фондирование в ставке предложения, потолок господдержки). Отдельный модуль, а не часть decision: decision зависит от products, и ставка в decision дала бы цикл между модулями.

## Ключевая ставка

Запись — ставка и дата, с которой она действует: `effective_from`, `value` (% годовых, 0–100, два знака), `decided_on` (дата решения совета директоров, не позже `effective_from`), `source` (`admin`, позже `cbr`), `note` (до 500 символов), `created_by`, `created_at`. Таблица `market_key_rates`, ключ — `effective_from`.

- **На дату `d` действует** запись с наибольшим `effective_from ≤ d`. Даты — московские: ставка Банка России начинает действовать с московского дня. `effective_from` админ вводит сам: обычно это следующий рабочий день после решения, система его не вычисляет.
- **Нет записей — значение из настроек.** Если на дату ничего не действует (пустая БД, первый запуск, тесты), берётся `KEY_RATE` и в ответе `source: "settings"`, `effective_from: null`. Сид записей не заводит.
- **Прошлое не правится.** Изменять записи нельзя (`PUT` нет). Удалить можно только запись с `effective_from ≥ сегодня` — ещё не действующую или ошибочно введённую сегодня. Прошлые записи — история, по ним принимались решения (решение и так хранит свою `key_rate`).
- **Без кэша.** Ставку читают одним запросом по индексу на каждую команду, событие или HTTP-запрос, поэтому новая запись действует сразу, без перезапуска.

`CATALOG_KEY_RATE` (ключевая, при которой заданы ставки каталога) остаётся в настройках: это свойство данных каталога, а не рынка.

## API

| Метод | Путь | Права | Ответ |
|---|---|---|---|
| `GET` | `/market/key-rate?on=YYYY-MM-DD` | публично | `{value, effective_from, source}`; `on` — по умолчанию сегодня |
| `GET` | `/market/key-rates` | `scoring.read` | `{current, items}`: история, новые сверху |
| `POST` | `/market/key-rates` | `scoring.update` | 201, запись; 409 `conflict` — дата занята; 422 — `value`, `decided_on` или `note` не проходят |
| `DELETE` | `/market/key-rates/{effective_from}` | `scoring.update` | 204; 409 `invalid_transition` — запись уже действовала; 404 — нет такой |

Права — как у версий кредитной политики. Действующая ставка открыта: это публичные данные, калькулятор может показывать «ключевая 14%».

У записи в истории бэкенд считает `in_force` (действует сегодня) и `removable` (её можно удалить), чтобы фронт не повторял правила.

```json
{
  "current": { "value": "14.00", "effective_from": "2026-10-27", "source": "admin" },
  "items": [
    { "value": "13.50", "effective_from": "2026-12-21", "decided_on": "2026-12-18", "source": "admin",
      "note": "решение СД от 18.12", "created_at": "2026-12-18T15:10:00Z", "in_force": false, "removable": true },
    { "value": "14.00", "effective_from": "2026-10-27", "decided_on": "2026-10-23", "source": "admin",
      "note": null, "created_at": "2026-10-26T09:00:00Z", "in_force": true, "removable": false }
  ]
}
```

## Событие `KeyRateChanged`

`market.events`, ключ — дата ставки. Уходит через outbox в той же транзакции, когда меняется ставка, действующая сегодня:

- `POST` записи с `effective_from ≤ сегодня`, если она стала действующей, и `DELETE` записи с сегодняшней датой — сразу;
- запись, введённая заранее, — в день начала действия: фоновая задача market раз в час (`RUN_BACKGROUND_JOBS`, `AnnounceDueKeyRatesUseCase`) находит записи с `effective_from ≤ сегодня` и `announced_at IS NULL`, ставит `announced_at` и шлёт одно событие с действующей ставкой. Ставка «на 21.12» разойдётся утром 21.12, в пределах часа.

В событии — действующая ставка (`value`, `effective_from`; `null` — снова значение из настроек). decision по нему будит ночной пакет и пересчитывает предодобрения по новой ставке ([decision](decision.md)).

## Фасад

`MarketFacade.key_rate(day=None) -> KeyRateDTO(value, effective_from, source)` — ставка, действующая на `day` (по умолчанию сегодня по Москве).

- products: `ProductService` берёт ставку на каждый вызов через порт `KeyRates` (`products/infrastructure/key_rates.py`) и сдвигает каталог на `ставка − CATALOG_KEY_RATE`. Без модуля market (юнит-тесты products) сдвига нет. Ведение каталога (`GET /products/all`) показывает рядом со хранимыми ставками блок `market_rate` — те же ставки по действующей ключевой ([products.md](products.md#ставки-за-ключевой)).
- decision: обработчики команд и событий берут ставку на каждую команду, ночной пакет — один раз на проход (`PreApprovalTransaction.market`), превью версии политики — на запрос (`KeyRateDep`), сид предодобрений — через фасад.

## Что не входит

- **Подтягивание ставки с cbr.ru.** У Банка России есть веб-сервис `DailyInfoWebServ/DailyInfo.asmx` с методом ключевой ставки. Если его подключать — фоновая задача за флагом (по умолчанию выключен), `source=cbr`, адаптер за портом: стенд жюри не должен зависеть от сети.
- **Выданные офферы** по заявкам при смене ставки не пересчитываются: их условия зафиксированы на 7 дней.
