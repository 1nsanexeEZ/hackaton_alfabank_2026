# ML для команды без ML-опыта

> **Статус на 23.10.2026:** план, написанный до выдачи кейса, документ остаётся как история. В прототипе скоринг — объяснимая PD-модель на скоркартах с биннингом и WoE, без обученных моделей и ноутбуков ([`docs/modules/scoring.md`](modules/scoring.md)); AI-ассистент — отдельная ветка (ишью #99), ML-модель рядом с PD — ишью #108.

Цель — не «выучить ML за неделю», а закрыть ML-часть кейса минимальным, но честным и объяснимым решением.
Точные требования узнаем 19.10 в 21:00, поэтому план рассчитан на два вероятных сценария.

## Что вообще может потребоваться

По формулировке трека («ИИ-кабинет, который помогает предпринимателю выбрать и оформить подходящий кредит») и словам оргов «данные дадут, их нужно использовать» видно две разные по сути задачи:

| | A. LLM-ассистент | B. Модель на табличных данных |
|---|---|---|
| Что это | Чат, который подбирает продукт, отвечает на вопросы, ведёт по заявке | Скоринг / вероятность одобрения / рекомендация продукта по данным клиента |
| Это ML? | Нет, это **инженерия**: API, промпты, tool calling | Да, классический ML |
| Обучаем что-то? | Нет | Да, на ноутбуке за минуты |
| Кому | Бэкенд 2 | DevOps после инфры (день 2+) или тимлид; ревьюит второй |

**Чего не делаем:** не обучаем и не дообучаем LLM (нет GPU, нет времени), не пишем нейросети с нуля, не тащим тяжёлые фреймворки (LangChain, агентные фреймворки) — свой цикл tool calling на 50 строк проще и понятнее экспертам.

## A. LLM-ассистент

### Что понять (2–3 часа)
- system prompt, temperature, токены и контекстное окно;
- **tool calling (function calling)**: модель не считает ставки сама, а вызывает наши эндпоинты — `get_products`, `calc_payment`, `get_application_status`, `list_missing_documents`. Это главная защита от галлюцинаций: цифры приходят только из нашей БД;
- **structured output**: просим у модели JSON по схеме (Pydantic) — например, извлечь из свободного текста «нужно 2 млн на оборудование на 3 года» параметры заявки;
- **RAG** — только если дадут документы (условия продуктов, FAQ): эмбеддинги → поиск похожих кусков → подкладываем в промпт;
- guardrails: ассистент не обещает одобрение, не выдумывает условия, честно говорит «не знаю».

### Что читать
- Anthropic, «Building effective agents» — какие паттерны агентов реально нужны, а какие оверинжиниринг: https://www.anthropic.com/research/building-effective-agents
- Документация OpenRouter (бесплатные модели, OpenAI-совместимый API): https://openrouter.ai/docs
- Ollama (локальные модели): https://ollama.com
- GigaChat API (если кейс потребует отечественную модель): https://developers.sber.ru/docs/ru/gigachat/overview

### Архитектура
Один интерфейс `LLMClient` в бэкенде, провайдер выбирается через env:

```python
from openai import OpenAI

# OpenRouter
client = OpenAI(base_url="https://openrouter.ai/api/v1", api_key=os.environ["LLM_API_KEY"])
# Ollama (локально): base_url="http://localhost:11434/v1", api_key="ollama"
```

Пакет `openai` — это просто клиент для OpenAI-совместимого API, с ним работают OpenRouter, Ollama, vLLM и многие другие. Смена провайдера — смена `base_url` и модели в `.env`.
Если LLM недоступна, кабинет работает без ассистента (в 2025 бесплатная модель у одной команды стала платной прямо во время проверки).

## B. Модель на табличных данных

### Что понять (3–4 часа) — минимум, без которого нельзя
- train / validation / test split и **почему нельзя проверять на тех же данных, на которых учили**;
- переобучение;
- **утечка таргета (target leakage)** — самая частая ошибка новичков: признак, который «знает ответ» (например, статус заявки при предсказании одобрения). Даёт фантастический скор и мгновенный провал у экспертов;
- метрики классификации: ROC-AUC, precision/recall, F1; дисбаланс классов;
- категориальные признаки;
- объяснимость: важность признаков и SHAP — «почему модель решила так». Банку это важнее, чем +0.01 к метрике.

### Почему CatBoost
Сам работает с категориальными признаками, хорош на дефолтных параметрах, быстро учится на CPU, умеет считать SHAP без дополнительных библиотек, документация есть на русском. Для табличных данных это стандартный сильный бейзлайн.

### Что читать
- Kaggle Learn: «Pandas», «Intro to Machine Learning», «Intermediate Machine Learning» — коротко, бесплатно, с практикой в браузере: https://www.kaggle.com/learn
- Учебник по ML от Яндекса — разделы про линейные модели, метрики, градиентный бустинг: https://education.yandex.ru/handbook/ml
- Туториалы CatBoost: https://github.com/catboost/tutorials
- mlcourse.ai (открытый курс ODS), если появится время глубже: https://mlcourse.ai

### Как модель попадает в продукт
Ноутбук (EDA, обучение, валидация) → `model.cbm` → загружается при старте FastAPI → эндпоинт `/score` возвращает вероятность + топ-3 фактора из SHAP → фронт показывает «почему так и что улучшить».
Ноутбуки с экспериментами **оставляем в репо** (`ml/notebooks/`) — в 2025 эксперты спрашивали «а где эксперименты?».

## Тренировка до 19.10, 21:00 (≈3 часа)

### Дрилл 1 — табличная модель (ML-владелец)
На открытом кредитном датасете German Credit пройти весь путь: загрузить → разбить → обучить → оценить → объяснить → сохранить.

```python
from sklearn.datasets import fetch_openml
from sklearn.model_selection import train_test_split
from sklearn.metrics import roc_auc_score
from catboost import CatBoostClassifier, Pool

df = fetch_openml("credit-g", version=1, as_frame=True).frame
y = (df.pop("class") == "bad").astype(int)          # 1 = плохой заёмщик
cat = df.select_dtypes(["category", "object"]).columns.tolist()
df[cat] = df[cat].astype(str)

X_tr, X_te, y_tr, y_te = train_test_split(df, y, test_size=0.2, stratify=y, random_state=42)

model = CatBoostClassifier(iterations=500, verbose=100, cat_features=cat)
model.fit(X_tr, y_tr)
print("ROC-AUC:", roc_auc_score(y_te, model.predict_proba(X_te)[:, 1]))

shap_values = model.get_feature_importance(Pool(X_te, cat_features=cat), type="ShapValues")
model.save_model("model.cbm")
```

Потом обернуть в эндпоинт FastAPI `/score`, который отдаёт вероятность и три самых влиятельных признака.
