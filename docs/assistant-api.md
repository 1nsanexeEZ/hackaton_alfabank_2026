# Умный помощник: контракт API

Контракт ведёт бэкенд, фронт подстраивается под него. Название «Умный помощник» — для пользователя; в коде, путях и ишью остаётся `assistant`.

Помощник — модуль backend `assistant`: ручки идут тем же адресом, что и остальной API (через nginx — `/api/assistant/…`, dev-сервер Vite проксирует `/api`). Устройство, модели и защита — в [`ai.md`](ai.md). Здесь только то, что нужно фронтенду. Схемы — в [`api/openapi.json`](api/openapi.json).

## Адрес и вход

- Адрес — база API кабинета (`VITE_API_BASE_URL`, по умолчанию `/api`). Источник тот же, что у сайта, CORS не нужен.
- Вход — тот же токен, что у остальных запросов кабинета: `Authorization: Bearer <access_token>`.
- Права: нужен `assistant.use` (выдан ролям клиента и андеррайтера; есть в `permissions` ответа `GET /me`). Без токена `401`, без права `403`. Клиент спрашивает о заявках своих компаний: чужую заявку помощник не покажет — ответ тот же, что и «нет такой заявки».
- Без модели помощник отвечает по шаблонам, поэтому он доступен всегда, когда доступен backend. Фронт показывает кнопку всегда и состояние берёт из `GET /assistant/status`; не ответил за 3 с или сетевая ошибка — состояние «недоступен».

## Ручки

### `GET /assistant/status` — без входа

```json
{ "enabled": true, "mode": "llm", "provider": "local", "model": "qwen3:4b-instruct-2507-q4_K_M", "host": "ollama", "reachable": true, "reason": null }
```

- `mode`: `llm` — отвечает модель; `rules` — отвечает по шаблонам (модель выключена, недоступна или ещё не скачана). Оба режима рабочие, в `rules` ответы короче.
- Отвечает сразу, не дожидаясь сервера модели: `reachable` — последняя проверка, она идёт в фоне не чаще раза в 10 с (первый запрос после старта ждёт её не больше 0,5 с). Укладывается в 3 с порога фронта и без модели.
- `provider`: `local` — модель рядом с приложением, `api` — внешний OpenAI-совместимый API, `off` — без модели.
- `enabled: false` — модели нет или настройка отклонена, `reason` — почему. Помощник всё равно отвечает по шаблонам.
- Для подписи в интерфейсе: `llm` → «ИИ отвечает», `rules` → «Отвечает по шаблонам», нет ответа сервиса → «Недоступен».

### `GET /assistant/applications` — заявки, о которых можно спросить

Заявки компаний, где пользователь участник, по номеру. Сотруднику банка — пустой список: он спрашивает по id заявки.

```json
[{ "id": "uuid", "number": "2026-000123", "product_code": "…", "status": "…", "client_stage": "…" }]
```

### `POST /assistant/conversations` → `201`

```json
{ "id": "uuid", "created_at": "2026-10-25T10:00:00+00:00" }
```

### `GET /assistant/conversations/{id}` — история

Последние 200 сообщений, старые первыми.

```json
{ "id": "uuid", "created_at": "…", "messages": [
  { "id": "uuid", "role": "user|assistant", "text": "…", "created_at": "…", "application_id": "uuid|null", "mode": "llm|rules|null" }
] }
```

### `POST /assistant/conversations/{id}/messages` — вопрос

Тело: `{ "text": "Что решил банк по заявке?", "application_id": "uuid|null" }`. Текст — не пустой, до 1000 символов. Без `application_id` помощник сам берёт единственную активную заявку пользователя, если вопрос про неё.

- Обычный ответ (`Accept: application/json`):

  ```json
  { "message_id": "uuid", "text": "…", "mode": "llm|rules", "intent": "decision|status|products|payment|greeting|off_topic|injection|internal_data", "application_id": "uuid|null", "fallback_reason": null }
  ```

- Поток (`Accept: text/event-stream`) — для набора текста по мере ответа:

  ```
  event: status   data: {"state":"thinking"}
  event: delta    data: {"text":"часть ответа"}      (повторяется)
  event: done     data: {…тот же объект, что в обычном ответе…}
  event: error    data: {"detail":"assistant failed"}
  ```

  Строки `: ping` — keep-alive, их игнорируют. Поток не отдаёт `delta` до готовности всего ответа: сначала `thinking`, потом текст кусками — это постпроверка ответа до показа.

## Ошибки

Тело ошибки — как у всего API: `{ "code": "…", "message": "…" }`.

| Код | Когда | Что показать |
|---|---|---|
| 401 | нет или просрочен токен | предложить войти |
| 403 | нет права `assistant.use` | «Помощник вам недоступен» |
| 404 | нет такого диалога или заявки | начать новый диалог |
| 422 | вопрос пустой или длиннее 1000 символов | подсказка в поле ввода |
| 429 | лимит вопросов в минуту, заголовок `Retry-After` (секунды) | «Слишком часто, повторите через N с» |
| 502/503, сеть | backend недоступен | «Помощник временно недоступен», кнопка «Повторить» |

Диалоги хранятся в базе backend и переживают перезапуск. Фронт держит `conversation_id` в `sessionStorage`; на `404` молча начинает новый диалог.

## Что помощник не говорит

Клиенту — только то, что видно клиенту в кабинете: решение, условия, причины простым языком, чего не хватает, что улучшить. Без скора, факторов, кодов причин, трассы правил и данных БКИ — ни в ответе, ни в истории.
